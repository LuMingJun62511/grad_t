# 训推数据生成规范 (V6)

> 本规范描述：以「产品树 + 百科MD」为起点，生成 SFT 训练与评测数据的方法。
> 读者：任何人或大模型，按本规范可独立实现生成脚本。

---

## 0. 背景与目标

### 目标

将结构化的产品知识（产品树）+ 自然语言语料（百科MD）转化为可训练的 SFT 数据，并配套可自动评分的评测数据。

### 方法论来源

- 论文 StructTuning 的 SCPT/SSFT 两阶段设计（mindmap 条件训练 + 结构感知QA）
- 自有设计：指代拼接与多跳推理（训评分离）

### 训评分离总原则

> **模型必须见过所有知识，但没见过评测的问法形态。**

- 训练集：所有 SPU 的所有知识都出现，问法直接（「X 是什么？」「X 多少钱？」）
- 评测集：知识全部见过，但问法需要组合/推理（「有X特性的是谁家的什么？」）
- 禁止：评测问题原样或近似出现在训练集中

## 1. 输入原料

### 1.1 产品树 (JSON)

结构：`公司 → 产线 → 系列 → 代 → SPU`，每层节点含结构化字段。

```json
{
  "name": "华为", "type": "公司",
  "children": [{
    "name": "手机", "type": "产线",
    "children": [{
      "name": "Mate 系", "type": "系列",
      "children": [{
        "name": "Mate 80 系", "type": "代",
        "children": [{
          "name": "Mate 80 Pro", "type": "SPU",
          "attrs": {
            "positioning": ["商务旗舰", "全能旗舰"],
            "talking_points": ["麒麟9030", "WiFi7", "6.9寸微曲屏"],
            "generation": "最新款",
            "status": "在售"
          }
        }]
      }]
    }]
  }]
}
```

产品树是**唯一 ground truth**：所有评测答案必须能从树中推导。

### 1.2 百科 MD 语料

按「代」为单位组织的自然语言语料，每篇一个文件。章节结构为：

```markdown
# 华为 Mate 80 系列

> 来源: 百度百科 | 产品树路径: 华为 > 手机 > Mate 系 > Mate 80 系

## 系列概述
{自然语言段落}

## 产品矩阵
{该代下所有SPU及一句话定位}

## 各型号详解
### Mate 80
{该型号核心参数、特色功能}

## 技术亮点
{芯片、屏幕、影像等维度}

## 市场反响
{销量、评价}

## 产品事件
{具体事件}
```

MD 语料是自然语言知识的来源，用于生成 SCPT 正文和 SSFT 事实类 QA。

## 2. 生成管线

```
产品树 ─┬─→ [SCPT前缀] ──┐
         │                 ├─→ train_scpt.jsonl (预训练数据)
百科MD ──┴─→ [切片+标题] ──┘

产品树 ──→ [树字段QA] ────┐
                          ├─→ train_sft.jsonl (微调数据)
百科MD ──→ [MD事实QA] ────┘

产品树 ──→ [指代拼接] ────┐
                          ├─→ eval.jsonl (评测数据)
产品树 ──→ [多跳推理] ────┘
```

### 2.1 MD 切片（语义保护原则）

- **按章节切**，不按固定字数硬切
- 一个 `##` 章节 = 一个或多个 chunk
- 章节过长（>800字）时按段落切，不跨小节合并
- 每个 chunk 记录其来源章节标题（用于后续起标题）

### 2.2 知识点标题生成

每个 chunk 由 LLM 生成一个摘要标题（知识点标签），规则：

- 输入：chunk 全文 + 所在产品树路径
- 输出：10-25 字的抽象化标题，**不含具体产品型号**（型号属于结构信息）
- 例：Mate 80 技术亮点章 → 「旗舰手机的卫星通信与三模通信系统」
- 标题与正文共同构成知识点；标题列表可组织成知识结构（本项目中结构已由产品树给定，标题仅用于 SCPT 模板中的「本节介绍」）

### 2.3 SCPT 数据（StructTuning 论文路线）

格式：`{"input": 前缀, "output": 正文}`，loss 只计算 output 部分。

前缀模板（多样化轮换，防止过拟合）：

```
在{产线}的领域知识体系中，结构如下:
{mindmap 树状渲染}
其中关于{知识点标题}的详细内容为:
```

- mindmap 渲染自产品树，**渲染全树**（论文做法），当前 chunk 所在分支可加粗/标记
- 模板池 ≥5 种表述，随机轮换
- 遍历所有 chunk 后，追加「结构回忆」样本：output = 完整 mindmap 渲染

### 2.4 SSFT 数据

格式：`{"instruction": Q, "output": A}`，A 中**带知识路径**。

```
Q: Mate 80 Pro 搭载什么处理器?
A: [华为 > 手机 > Mate 系 > Mate 80 系]
   Mate 80 Pro 搭载麒麟 9030 处理器。
```

两类来源：

| 来源 | 问法 | 覆盖 |
|------|------|------|
| 树字段 | 芯片/定位/代际/状态/系列归属 | 每个SPU × 每字段 × 2-3种问法 |
| MD事实 | 从chunk中提取的事实 | 每个chunk × 1-2条 |

QA 生成可由 LLM 辅助，但**答案必须可回溯**到树字段或 MD 原文。

### 2.5 评测数据（自有设计）

格式同 SFT，但**答案不带知识路径**（裸答案，评分用）。

**A类：指代拼接**（~70%）

原理：用独有特性间接指代产品，逼模型走「特性→产品→归属」的多步推理。

```
Q: 8000nits 峰值亮度的「超透亮灵珑屏」是哪家公司的什么产品?
A: 华为 Mate 80 Pro Max

Q: 「5A」网络标识是华为哪个系列的通信特性?
A: Mate 系列 (Mate 80 系)
```

- 特性必须**独有**（只属于一个SPU/一个代），保证答案唯一
- 提问层级覆盖：公司/产线/系列/代/SPU 五层
- 评分：exact match

**B类：多跳推理**（~30%）

原理：问法需要组合两条以上独立知识。

```
Q: 华为 Mate 80 Pro 和 FreeClip 2 都搭载了什么芯片品牌?
A: 麒麟 (麒麟9030 / 麒麟A3)

Q: Mate 80 系列中, 性能提升42%的机型用什么屏幕?
A: 超透亮灵珑屏 (1.5K双层OLED)
```

- 需组合跨SPU或跨维度知识
- 评分：exact match 或答案集合匹配

### 2.6 评测可行性约束（每条评测必须满足）

| 检查项 | 要求 |
|--------|------|
| 输出格式 | 固定可解析：单个值/顿号分隔列表 |
| 答案唯一性 | 独有特性或多跳推理保证唯一 |
| 可回溯性 | 答案可从产品树/MD原文验证 |
| 问法新颖性 | 不在训练集中出现（人工抽查+相似度检查） |

---

## 3. 输出文件格式

```
data_/v6/
├── train_scpt.jsonl   # 条件预训练数据 {"input": ..., "output": ...}
├── train_sft.jsonl    # 微调数据 {"instruction": ..., "output": ...}
├── eval.jsonl         # 评测数据 {"instruction": ..., "output": ..., "_scoring": ..., "_gold": ...}
└── chunks.jsonl       # 中间产物 {"chunk_id": ..., "tree_path": ..., "title": ..., "content": ...}
```

## 4. 质量门槛

1. 每条数据人工可验证（能指出知识出处）
2. 评测数据全自动评分（exact match / 列表F1）
3. 无脏数据：无广告、无繁体、无产品混淆
4. 覆盖检查：每个 SPU 在训练集中出现 ≥N 次（N 视字段数定）
5. 评测抽查：随机 20 条人工过目，全部可通过「知识见过、问法没见过」检验
