# 今日目标 (2026-08-30)

## 公司带来的发现与想法

- 三元组 → 题目的转换，大概率少不了 AI 来搞（模板写死不够语义通顺）
- 需要设计**一整套 prompt**，保证：语义通顺、问题合理
- 追求**模板多样性**，但机制没想好（今日要解决的点）
- 之前一直卡在产品树最底层（SPU 层）用元组出题，**把树忘了**——后面要能用上整棵树

## 任务列表

### 目标1（今日主线）：三元组 → 题目的 Prompt 设计

- [ ] 梳理三元组的类型清单（is_a / has_chip / has_feature / positioned_as / 代际 / 状态...）
- [ ] 设计核心 prompt（三元组 → 多条自然语言 QA）
- [ ] 解决多样性问题：确定机制（多样模板池？样式标签？一次多生成？）
- [ ] 小规模验证：拿 Mate 系三元组试跑，人工检查语义通顺度与问题合理性

### 目标2（目标1完成后再启动）：让题目生成用上产品树

- [ ] 不只是 SPU 层元组，让树的上层（产线/系列/代）也参与出题
- [ ] 树路径作为 prompt 上下文注入（系列级归纳题、代际对比题）

## 验证标准

- 生成的题目：语义通顺、无模板腔、答案可从三元组唯一回溯
- 同一条三元组能产出 ≥3 种不同风格的问法
- 人工抽查 20 条，通过率 ≥90%

## 待办 (讨论中产生的遗留)

- [ ] **树上多跳指代题**（台阶二扩展方向）：先训会背特性，再指代过去读树上其他节点的属性。例："屏幕是A材质且具有X架构的那款华为手机，它的系列别名是什么？"——两个条件交集定位 SPU（如 Mate 80），再顺树爬取系列别名作答。1-2 归属链是这类题的地基（直接训树结构）。
- [ ] **特性 (has_feature) 元组待细化**：当前已从所有题型输入中剔除。原因：同实体多条"特性"元组在正向题"X有什么特性"下会造冲突事实（同一问题多个答案）。细化方向：把特性值翻译成具体谓语（如"支持天通卫星通信吗"→谓语=支持天通卫星通信），或保留给反向指代题型（2-1 特性值是最好的指代物）。回头再处理。
- [ ] **孤岛复查**：出完所有题型后，检查是否有元组只被一种题型使用（孤岛），再决定筛除或补出口。
- [ ] **模板轮换已外部化**：runner 用 hash(实体,关系,值)%N 伪随机轮换模板，LLM 不自己选。若模板池扩充（>4），检查分布均匀性。
