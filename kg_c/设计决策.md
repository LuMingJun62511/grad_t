## 2026-08-31

### D9: 2-3 的疏漏——prompt 给全量属性 = 打开"蒸馏逃逸口"（未修，时间原因暂缓）

**疏漏**：2-3 现有 prompt 把两个实体的**全部属性**塞给 LLM，让它自己挑对比关系。后果：
1. LLM 挑元组外/单边有值的关系 → 用**自己的知识**补答案（"Mate 80 未提及防水等级"就是这么来的）
2. 用自己的知识回答 = **蒸馏模型**，不是注入我们的元组知识——知识注入的根基被破坏

**正确设计**（已定未改）：
- 第一步[挑]：确定性算可比对项（同层级配对 + 同关系两边都有值 + 值不同），或 LLM 提候选
- 第二步[人审]：审"可比对项"清单（关系名+值对，一屏几百条，便宜）
- 第三步[出题]：审过的可比对项作为输入，LLM 只填空出题，无逃逸口

**拒绝在答案里出现**：拒答本身可以（语料确实没有），但拒答的来源必须是元组（"语料里没有"），不是模型知识（"现实中没有"）。

### D8: 2-2 多条件筛选——数据要从宾语出发组织（用户修正）

**决策**：2-2 的数据必须**提前组织**——在每个 scope（品类）内，以宾语为根建倒排索引：宾语值 → 拥有它的主语集合。这个倒排索引就是题目的**真值**（ground truth），生成与核验都从它走。

**与 2-3（横向对比）的本质区别**：
- 2-3 的数据组织是**实体对**（两个同代实体配对，找同关系异值）
- 2-2 的数据组织是**倒排**（宾语为根，n 叉展开找所有主语）——这就是用户之前说的"以宾语为根搞 n 叉树"

**核验逻辑**：
```
出题: 选一个宾语值 O + 关系 R + scope S
      → 倒排索引查 (S 内, R=O 的主语们) = 答案真值
核验: 模型答案 vs 倒排索引的真值集合, 列表 F1
没有倒排组织, 答案真值无从谈起
```

**scope 的角色**：scope 是倒排索引的分桶维度（不同品类各建一张倒排表），不是简单放大缩小——同一宾语值在不同 scope 内展开的主语集合不同，题目在 scope 内才有确定答案。

### D7: 2-1 反向指代改为「双条件联合 + 品类范围」

**决策**：单特征反向指代作废。新设计：题干给品类范围 + 两条属性条件，问同时满足两条件的产品。

**理由**（用户提出）：
- 三元组是**充分不必要条件**：(S,R,O) 只说明 S 有 O，不保证 O 唯一属于 S。数据里的"唯一"不等于现实唯一，单特征反向指代基本都是错题
- 满足一个条件容易撞，两个条件同时满足就很难撞了
- 组合唯一性可以**程序验证**（同品类内无第二个实体同时满足两条件）
- 加品类范围（手机/耳机大类）相当于第三个约束，且缩小搜索空间

**实现**：gen_inputs_21.py 对每个实体取属性两两组合，验证组合在同类目内唯一后生成输入包。

### D1: 1-4 真伪确认——砍掉确认样本，保留少量否定样本

**决策**：1-4 不再生成 truth=真 的确认样本；truth=假 的否定样本保留，但只采样 ~10%（约 20-30 条）混入训练集。

**理由**：
- 确认样本是 1-1 的冗余：正向配对 (S,R,O) 已在 1-1 教会，"X 是麒麟9030吗→是"是同一知识的句式变换，无增量，纯浪费 token 和时间
- 否定样本有独特价值：抗"顺杆爬"——LLM 对问句中塞入的错误值容易默认肯定，需要少量否定样本教它"敢说不"
- 但否定样本当前的构造方式（随机取其他实体的值）教的是低层次模式"值没见过→答不是"，并非真正的知识边界。真正的边界是"麒麟9020 是 Mate 80 标准版的"这种带归属的否定——留待特性元组细化时一起解决
- 定位变化：1-4 从独立题型降级为"1-1 的否定变体"，小剂量混入

### D2: 特性 (has_feature) 元组暂弃

**决策**：特性关系从所有题型输入中剔除，待细化。

**理由**：同实体多条特性元组在正向题下造冲突事实（同一问题多个答案）。细化方向：特性值翻译成具体谓语，或保留给反向指代（2-1）。

### D3: 树上多跳指代题是台阶二的方向

**决策**：产品树主要用于台阶二——先训会背特性，再指代过去读树上其他节点的属性（"屏幕A材质且有X架构的那款手机，它的系列别名是什么"）。1-2 归属链是这类题的地基。

### D4: 模板多样性 = 外部伪随机轮换

**决策**：模板池放在 runner（README.md），用 hash(实体,关系,值)%N 轮换，LLM 只填空不选模板。

**理由**：LLM 自由选择模板时全部倾向第一个（实测 7/7 全用模板1），分布完全不均衡。

### D5: prompt 文件约定

**决策**：每个题型文件夹内，prompt.txt 只放纯 prompt 正文（含设计意图+示例+占位符），README.md 放题型定义/模板池/输入格式/质量自检，output.jsonl 流式落盘，审阅.xlsx 供人工评审。

**理由**：prompt 单独成文件才能直接被 runner 或外部工具使用；设计意图和示例入 prompt 能显著提升生成质量（1-2 实测）。

### D6: 多值关系是反复踩坑点

**决策**：多值关系（配色/产品定位）在题型间要特殊处理。

**已踩的坑**：
- 1-1：多值关系造冲突事实（"X 的配色是什么"有 4 个答案）→ 1-1 只收单值关系，多值归 1-3
- 1-4：否定样本生成时，实体自己的另一个真值被当成"假"样本 → 修法：否定值排除该实体自己的所有值
