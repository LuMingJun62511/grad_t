# 三元组 → 题目 Prompt 设计 (V1 草案)

> 今日目标1。核心问题：如何用 AI 把三元组变成语义通顺、问题合理、**问法多样**的问答对。

---

## 一、多样性机制：样式池 (Style Pool)

### 机制

```
样式池 = 8 种提问风格，每种含 {名称, 说明, 范例}

一次调用 = 一个三元组包 + 随机抽取 K 种样式 → 生成 K 条问答
样式不重复抽取，多次调用间随机轮换
```

**为什么用样式池而不是让模型自由发挥**：
- 自由发挥的问题：模型倾向输出相似句式（全是"XX是什么？"），多样性不可控
- 样式池给每种风格一个明确的锚，保证覆盖面
- 后续可扩展：让 LLM 在池外「自创样式」（实验第二阶段）

### 样式池 (V1: 8种)

| # | 样式 | 说明 | 范例（三元组: Mate 80 Pro → 麒麟9030） |
|---|------|------|------------------------------------------|
| 1 | 直接询问 | 标准信息查询 | "Mate 80 Pro 搭载什么芯片？" |
| 2 | 口语闲聊 | 轻松随意，像朋友聊天 | "Mate 80 Pro 的处理器是啥来着？" |
| 3 | 场景代入 | 带购买/使用场景 | "想入手 Mate 80 Pro，这机子芯片怎么样？" |
| 4 | 确认式 | 已知答案求确认 | "Mate 80 Pro 是不是用了麒麟9030？" |
| 5 | 属性展开 | 追问细节/含义 | "Mate 80 Pro 的麒麟9030是什么水平？"（⚠️答案必须可回溯） |
| 6 | 指代反问 | 用值反指实体 | "麒麟9030 用在华为哪款手机上？"（⚠️需唯一性） |
| 7 | 选择题式 | 给选项让模型选 | "以下哪款搭载麒麟9030？A. Mate 80 B. Mate 80 Pro C. Mate 80 Pro Max"（⚠️评测用） |
| 8 | 对比引出 | 跨实体对比 | "Mate 80 和 Mate 80 Pro 的芯片有什么区别？"（⚠️需同代多实体数据） |

### 约束条件（每种样式必须遵守）

- ⚠️ 标记的样式有前置条件，不满足时该样式跳过
- 答案必须**严格可回溯**到输入三元组，不得编造
- 问题不得直接复述三元组（如"麒麟9030是Mate 80 Pro的芯片吗"太机械）

## 二、Prompt 结构

### 输入格式

```json
{
  "entity": "Mate 80 Pro",
  "tree_path": "华为 > 手机 > Mate 系 > Mate 80 系列",
  "triples": [
    {"relation": "is_a", "value": "Mate 80 系列"},
    {"relation": "搭载芯片", "value": "麒麟9030"},
    {"relation": "产品定位", "value": "商务旗舰"},
    ...
  ]
}
```

三元组**打包**输入（一个 SPU 的所有三元组一次给），而不是单条三元组单独调——对比式问题需要同实体多值。

### Prompt 正文 (V1)

```
你是电子产品知识问答语料生成器。给定一个产品和它的事实三元组，
为每种指定样式生成一条自然语言问答对。

【输入】
产品: {entity}
所属路径: {tree_path}
事实三元组:
  - is_a: {值}
  - 搭载芯片: {值}
  ...

【任务】
按以下 N 种样式各生成 1 条问答:
{样式1}: {说明}
{样式2}: {说明}
...

【硬性要求】
1. 问句像真人说话，禁止模板腔（禁止出现"请问""请告诉我"等书面套话堆积）
2. 答案只使用输入三元组中的事实，禁止编造型号、参数、价格
3. 答案要求简洁（≤30字），不解释推理过程
4. 每种样式只输出一条，不重复、不遗漏
5. 若某样式的前置条件不满足，输出 "SKIP"

【输出格式】JSON数组:
[{"style": "直接询问", "question": "...", "answer": "..."}]
```

### 关键设计点

1. **样式在 prompt 内展开**（不是让模型选样式）——可控
2. **答案≤30字 + 只许用三元组事实**——保证可回溯、可评分
3. **SKIP 机制**——有前置条件的样式不硬凑
4. **每次调用随机抽 K=5 样式**——同一三元组包多次调用产出不同组合

---

## 三、实验计划

1. 取 Mate 80 系列 5 个 SPU，每个 SPU 打包三元组 → 5 个测试输入
2. 每包抽 5 种样式 → 预计 25 条问答
3. 人工检查：语义通顺度、模板腔、答案可回溯性
4. 记录样式池中哪些样式产出质量差 → 迭代样式池

## 四、待验证的问题

- [ ] 样式池 8 种是否够？是否需要分"通用样式"和"品类专属样式"（手机有芯片，耳机没有）？
- [ ] K=5 一次调用是否太多导致质量下降？K=3 和 K=5 对比？
- [ ] 对比式（样式8）的答案可回溯性最差，是否第一阶段先砍掉？
