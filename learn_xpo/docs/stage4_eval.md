# 阶段4：评测与复盘 —— 五件套

**学什么**：怎么判断训练到底有没有用——评测集分层、指标定义、以及把每个现象映射回天花板概念。

## 1. 评测集三层（每个测一层天花板）

| 评测集 | 内容 | 测什么 |
|---|---|---|
| `test_in_dist.jsonl`（100 条） | 与训练同源、同分布的留出样本 | "学会了没有"（模板与机制的记忆） |
| `test_ood.jsonl`（12 条） | 人工写的餐厅/职场/恋爱文本，非产品域 | **机制抽象 vs 表面捷径**（数量天花板二） |
| `test_seed.jsonl`（~152 条） | 人工种子，与训练语料零重叠 | 人评兜底：老师的偏差有没有被继承（天花板一） |

三个集分开报数，不要合并。**in_dist 高、ood 低 = 学到了表面没学到机制**——这正是 5 条/类小数据最可能的结果，如实记录。

## 2. 指标定义与用法

`python scripts/eval.py --preds <预测文件> --gold <金标文件>`

| 指标 | 含义 |
|---|---|
| 解析率 | 3.1/3.2 都能解析的比例（契约遵守度） |
| 二分类 Acc | 判断对错（只在解析成功样本上算） |
| 机制 Acc | 20 路机制对错（相关性拧强后的"硬指标"） |
| 双对 Acc | 两项都对 |
| 平均输出长度 | 长度爆炸/坍缩报警器 |
| 机制分布 / 分极性召回 | 类别坍缩、全答"是反讽"等捷径的探测器 |

预测文件来自 `swift infer`（对 base、SFT、DPO、GRPO 各跑一次，注意 base 跑 test 时
也走同一个 system prompt，这样四档可比）。`eval.py` 兼容 swift infer 输出的 `response`/
`predict`/`messages` 三种字段形态；**preds 与 gold 按行对齐**，别打乱顺序。

## 4. 失败模式 → 天花板映射表

| 观察到的现象 | 对应的概念 |
|---|---|
| in_dist 好、ood 差 | 数量天花板二：学到表面特征而非机制 |
| 机制 Acc 显著低于二分类 Acc | 表面词泄露答案（弱相关的证据） |
| 解析率在 DPO/GRPO 后下降 | 契约被训练冲掉（偏好强度/kl 失衡） |
| 空壳四段、套话变多 | 天花板三 + reward hacking：奖励看不见推理质量 |
| 输出里出现训练集没有的"语境"编造 | D1 决策的背面：模型在补它被教会依赖的字段 |
| seed 集显著差于 in_dist | 天花板一：老师/生成器的系统性偏差被继承 |

## 5. 复盘问题清单（每次训完过一遍）

1. 每一档的**机制 Acc 增量**是多少？二分类和机制的差距说明什么？
2. GRPO 的奖励曲线和测试 Acc 曲线**同向吗**？不同向说明什么？（弱相关的最直接证据）
3. 抽 5 条 GRPO 输出逐句读：哪句是推理、哪句是套话、哪句在复述输入？占比如何？
4. 对照实验（FORMAT_BONUS=0.1）的输出和主实验差在哪？
5. 如果要改进，改哪里最有效：数据（加量/加域）？契约（再拧强相关性）？
   还是奖励（加中间规则奖励，走 Phase 2 桥接方案）？——把答案写进决策日志。
