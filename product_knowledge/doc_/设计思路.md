# 设计思路

## 一、问题定义

做产品知识注入，核心需求是：**让大模型能听懂用户提到某个产品时的各种说法，并能准确联想对应信息**。

翻译成技术语言：给定一段带产品提及的自然语言文本，模型要能输出正确的实体链接元组（提及→产品→属性）。

## 二、为什么是实体链接而不是纯 QA

最初考虑过「Mate 是什么品类？→ 手机」这种一问一答。但问题是：

- 模型学到的不是知识，是「这个问题→那个答案」的映射
- 换一种问法就可能失灵
- 回答格式单一，不像真实对话

实体链接的优势：

```
输入: "华子那个三折的多少钱"
输出: {提及: "三折的", 产品: "Mate XTs 非凡大师", 属性: {价格: "¥18000起", 品类: "手机"}}

输入: "纠结要不要买M80PM"
输出: {提及: "M80PM", 产品: "Mate 80 Pro Max", 属性: {品类: "手机", 定位: "商务旗舰"}}
```

评测指标直接算准确率，不需要人工。

## 三、属性选择原则：话题度优先

一开始列了 50+ 个属性维度（材质、电池、分辨率……），但实际对话中没人聊这些。收敛到 **4 类有话题度的属性**：

| 维度 | 说明 | 例子 |
|------|------|------|
| 怎么叫它 | 别名、俗称、缩写 | "三折叠"、"M80PM"、"大杯" |
| 它是哪类 | 品类标签、定位标签 | "商务旗舰"、"阔折叠"、"医疗级" |
| 为什么被聊 | 话题锚点（1-3个） | "798g极致轻"、"写入高血压指南" |
| 什么时间语境 | 代际、状态 | "最新款"、"上代"、"即将发布" |

## 四、为什么评测集用模板、训练集分两版

**评测集（模板）**：
- 要求答案精确，不能有随机性
- 覆盖 10 种问题类型，692 条
- 评测指标：实体链接准确率

**训练集·模板版（脚本）**：
- 脚本能覆盖约 60% 的日常场景（别名消歧、价格、品类枚举、状态查询）
- 回答风格偏正式，句式重复
- 用于快速生成基线训练数据

**训练集·自然版（LLM）**：
- 覆盖模板搞不定的 40%（跨品类对比、话题闲聊、模糊口语、场景推荐、纠错消歧）
- 回答口语化，有观点，像朋友聊天
- 三路 Agent 并行生成，合并后 608 条零重复

## 五、为什么三路 Agent 并行

单路生成有几个问题：
1. 一次性塞 89 个产品数据，LLM 可能遗漏
2. 手机和非手机产品的问法差异大，混在一起容易偏向主力品类
3. 跨品类对比需要「站在更高处看全局」，单独一路效果更好

所以拆成三路：

```
Agent 1: 手机全部 SPU → 214 条（别名/介绍/对比/价格/闲聊）
Agent 2: 平板+本+表+耳机+屏+车 → 221 条（同上 + 场景推荐）
Agent 3: 跨品类对比+话题闲聊+模糊口语+纠错 → 173 条
```

## 六、可扩展设计

整个方案不绑定华为。换一家公司只需要：

1. 按 `华为产品属性.json` 的 schema 整理新产品 JSON
2. `python script_/gen_eval.py 新产品.json 评测集.jsonl`
3. `python script_/gen_train.py 新产品.json 训练语料_模板版.jsonl`
4. 按 Agent 分流方案生成自然版训练语料

脚本里的公司名、品类名、价格为动态读取，不硬编码。
