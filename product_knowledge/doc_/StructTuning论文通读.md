## 一句话说这篇论文在干什么

**让大模型像人类学生一样「按教科书目录」学习领域知识，而不是随机啃文本碎片。** 用 5% 的训练数据达到传统方法 100% 的效果。

---

## 0. 摘要（Abstract）

**做了什么**: 提出 StructTuning，一种结构感知的知识注入方法。分两个阶段——SCPT（按目录学知识）和 SSFT（按目录做练习）。

**效果**: 仅需 5% 的语料就能达到传统知识注入 100% 的性能。在医学 MMedBench 上，用 0.3% 数据就达到了 SOTA 方法 50% 的改进。

**代码**: github.com/alibaba/struxgpt

> 一句话：花更少的数据，学到更多的知识，因为带上了「目录结构」。

## 1. 引言（Introduction）

### 背景

大模型要成为领域专家，目前主要有两条路：
- **RAG（检索增强）**: 外挂知识库，查询时现找。问题：检索噪音大，特别是需要逻辑推理时，用户问题和知识库之间有语义鸿沟。
- **知识注入**: 通过训练把知识写进模型参数。主流做法是 CPT（继续预训练）+ SFT（监督微调）。问题：需要海量数据（几十亿 token），效果还不好。

### 核心洞察

**人类教育和当前 LLM 训练方式的对比**：

| 人类学生 | LLM |
|---------|-----|
| 按教科书章节顺序学 | 随机拼接文本块训练 |
| 学完后做针对性习题 | 随意 SFT 对齐对话 |
| 知识有结构、可追溯 | 知识碎片化 |

**所以**：为什么不模仿人类教育，让 LLM 也「按目录学」？

### 三个贡献

1. **SCPT + SSFT 两阶段策略**（结构感知的预训练 + 微调）
2. **可扩展的自动化数据构建框架**（不依赖人工标注）
3. **多模型多数据量的充分实验验证**

## 2. 方法总览（Methodology Overview）

### 整体框架（Fig.2）

```
原始语料（教科书等）
    │
    ▼
[Step 1] 提取知识结构
    ├─ spaCy 分句 → 合成不超过 2048 token 的 chunk
    ├─ Llama3-70B 给每个 chunk 起标题 → "知识点"
    └─ 专用 7B 模型把所有标题组织成树状结构 → "知识体系 mindmap"
    │
    ▼
[Step 2] SCPT — 结构感知的继续预训练
    每个 chunk 前面拼上: mindmap + "以下内容属于树的XX分支"
    模型只预测正文部分（mindmap 不计算 loss）
    遍历完所有知识点后，让模型回忆整棵知识树
    │
    ▼
[Step 3] SSFT — 结构感知的监督微调
    在知识树上 random walk → 生成 QA 对
    - 1条分支: 知识密集型 QA (KI-QA)
    - 2+条分支: 多跳推理 QA (2Hop-QA, MultiHop-QA)
    训练时答案带知识路径，评测时用裸问题
```

## 3. 方法细节

### 3.1 知识结构提取

**针对教科书**（有自然章节结构）：
1. spaCy 分段 → 合并成 ≤2048 token 的 chunk
2. Llama3-70B 给每个 chunk 写标题 → "知识点"
3. 把标题列表喂给专用 7B 模型 → 输出树状结构

**针对网络语料**（无自然结构）：
- 用聚类方法递归构建知识结构

**为什么不直接用 GPT-4 提取结构？**
实验证明：GPT-3.5 效果差不多但要花钱（26M token 需 $15），Llama3-70B 效果好但慢（1.5 小时）。他们蒸馏了一个 7B 模型，效果接近但只需 0.2 小时。

### 3.2 SCPT — 结构感知的继续预训练

**核心公式**: 把普通语言模型 p(text) 变成条件语言模型 p(text | mindmap)

**具体做法**:
```
训练样本 = [mindmap前缀] + [当前chunk的原文]
           ↑ 不计算loss       ↑ 只在这里计算loss
```

其中 mindmap 前缀长这样：
```
"In the realm of 生物化学, a conceptual mindmap is:
 生物化学
 ├─ 脂蛋白代谢概述
 │  ├─ 脂质代谢与胆固醇运输
 │  └─ 类固醇激素合成
 └─ 氮代谢
    └─ 氨基酸降解

 Within this organized layout, the detailed subsection on
 脂蛋白代谢 is described as:
 [原文chunk内容在这里]
```

**关键设计**:
- 用了 **20 种模板**随机轮换（Fig.A5），防止过拟合
- 遍历完所有知识点后，让模型**回忆整棵知识树**（公式2）
- 两个步骤在整个训练过程中交替进行

### 3.3 SSFT — 结构感知的监督微调

**QA 生成方式**:

```
在知识树上 random walk → 拿到路径 + 原文内容
                           │
            ┌──────────────┼──────────────┐
            ▼              ▼              ▼
        单知识点路径    双分支路径     多分支路径
            │              │              │
        喂 Llama3-70B  喂 Llama3-70B  喂 Llama3-70B
            │              │              │
            ▼              ▼              ▼
        KI-QA          2Hop-QA       MultiHop-QA
     (知识密集型)    (需要跨知识点推理)  (复杂多跳推理)
```

**训练格式**（关键创新）:
- 训练时：**答案中带知识路径 + CoT 推理**
- 评测时：**裸问题，不加任何提示**

> 这和我们的「指代拼接」异曲同工——训练给了指引，评测考验内化。

## 4. 实验

### 4.1 LongBench — 自由形式问答（知识记忆）

**数据**: 7 个子集, 1,350 个测试样本, 14K 阅读理解文章

**结果** (Tab.1, Llama2-7B):

| 方法 | 知识召回率 |
|------|-----------|
| CPT+SFT (传统) | 24.2% |
| SCPT+SFT | 26.7% |
| **SCPT+SSFT** | **31.5%** |

**关键发现**: 传统的 CPT+SFT 效果很差（24.2%），SCPT 提升到 26.7%（多了 2.5%），再加上 SSFT 提升到 31.5%（再提升 4.8%）。特别是多文档 QA（MultiDoc-QA）提升明显——这正是需要结构感知的场景。

### 4.2 MMedBench — 多选问答（知识应用）

**数据**: 6 种语言, 45K 训练 QA, 8,518 测试 QA

**核心结果** (Tab.2):

| 方法 | 平均准确率 | 训练数据量 |
|------|-----------|-----------|
| MMedLM2 (SOTA) | 67.75 | 25.5B token |
| Llama3+StructTuning (0.3%) | 65.36 | **76M token** |
| Llama3+StructTuning (5%) | **67.74** | **1.2B token** |

**震撼的数字对比**: MMedLM2 用了 25.5B token，StructTuning 只用 76M（0.3%）就达到了 MMedLM2 50% 的改进效果。扩展到 1.2B（5%）就**追平甚至超过** SOTA。

### 可扩展性 (Fig.6)

论文画了两条 scaling curve：
- 普通方法：要 100% 数据量才能达到 100% 效果
- StructTuning：**5% 数据量就达到 100% 效果**，预测 100% 数据量可达到 **133%** 效果

### 跨模型泛化 (Tab.3)

在 Llama2-7B/13B、InternLM2-7B、Llama3-8B 上都有效：
- InternLM2-7B: +4.46%
- Llama2-7B: +8.78%
- Llama2-13B: +6.17%

### 消融实验 (Tab.4) — 每个组件的作用

| 配置 | 英语准确率 | 说明 |
|------|-----------|------|
| 只 SFT | 44.54 | 基线 |
| CPT+SFT | 46.27 | +1.73 |
| SCPT+SFT | 46.50 | SCPT 本身提升 |
| **SCPT+SSFT** | **49.96** | +5.42% over 基线 |
| SCPT+SSFT* | 49.10 | +8K 额外 QA 对 |

**有趣发现**: 额外 8K 结构感知 QA（SSFT*）触发了**跨语言知识迁移**——用英语数据注入的知识，能帮模型用其他语言作答。

### 与其他方法对比

- **RAG**: 在 MMedBench 上没优势——医学问诊描述和教科书原文之间有巨大语义鸿沟，检索到的 chunk 经常不相关
- **AdaptLLM**（在 CPT 时加阅读理解 QA）: 几乎没提升
- **RAFT**（带噪声检索的 SFT）: 反而更差

## 5. 我的思考：与我们方案的映射

| StructTuning | 我们的 V3.x |
|-------------|-----------|
| 教科书原文 | 产品树 JSON + 百度搜索语料 |
| LLM 提取知识树 | product_tree.json（更精确，人工定义） |
| mindmap → chunk | corpus_index.json 的 tree_path |
| SCPT: mindmap + 原文训练 | 待实现 |
| SSFT: 带路径的 QA | V3.1 指代拼接（思路一致） |
| KI-QA / 2Hop-QA | 独有特性 → 反向追溯（类似 2Hop） |
| random walk 生成 QA | 图谱边 → 模板 QA（我们的方式） |

**我们可以直接用的**:
1. SCPT 的 20 种模板——把我们的产品树渲染成 mindmap 前缀
2. SSFT 的「训练带路径、评测裸问题」——我们的指代拼接就是这个思路
3. 消融实验的启示——结构本身（SCPT）的提升 + 结构驱动的 QA（SSFT）的提升是叠加的

## 6. 附录精华

### 知识结构提取（B.1）
- 不需要完美还原教科书目录，「差不多」就够用
- 蒸馏 7B 模型提取结构：22K 训练样本，1 epoch，成本极低

### 模板多样性重要（B.5）
- 固定 1 个模板 vs 随机 20 个模板 → 随机更好的效果
- 去掉知识树的顶层（目录章）→ 效果最差，说明顶层结构对知识组织最关键

### 随机 QA vs 结构感知 QA（B.6）
- 随机生成 8K QA 对（不基于结构）→ 平均准确率下降到 34.51%
- 结构感知生成的 8K QA → 提升到 38.27%
- 说明「有结构的 QA」远好于「随意 QA」

## 一句话总结

**这篇论文的核心洞察就是一句话：如果你让模型按照知识体系的结构来学习，它用 5% 的数据就能达到别人 100% 的效果。这个「结构」就是教科书目录——那棵树。**
