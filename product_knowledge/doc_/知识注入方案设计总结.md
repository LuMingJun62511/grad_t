# 基于知识图谱的 SFT 知识注入方案

> 从华为产品数据出发，探索一套「图谱构建 → 三元组 → 训推分离」的知识注入方法论

---

## 一、为什么要建图：三元组天然适配 SFT

### 问题

产品知识天然是结构化数据（公司、品类、系列、SPU、芯片、价格……），如果直接用 QA 对造 SFT 数据，有两个问题：

- **覆盖不全**：手写 QA 对只能覆盖部分知识，大量隐含关系被遗漏
- **训评不分**：评测题和训练题形式雷同，测不出真实的知识获取效果

### 方案

把产品数据建成一张**知识图谱**，节点是实体，边是关系。图上的每条边天然就是一个三元组（主谓宾），天然对应一条 SFT 训练语料。

```
产品属性 JSON                    知识图谱
─────────────                    ────────
{                              Mate 80 Pro
  "name": "Mate 80 Pro",         │
  "chip": "麒麟9030",     →      ├── is_a ──→ Mate 80 系列
  "series": "Mate 系列",         ├── has_chip ──→ 麒麟9030
  "price": "¥6499起"             ├── has_price ──→ ¥6499起
  ...                            └── positioned_as ──→ 商务旗舰
}

三元组: (Mate 80 Pro, has_chip, 麒麟9030)
  → QA: "Mate 80 Pro搭载什么芯片？" → "麒麟9030"
  → QA: "哪些产品搭载麒麟9030？" → "Mate 80 Pro, ..."
```

**一条三元组，正反两个方向，3-5 种问法模板 = 一条边产出 6-15 条 SFT 语料。**

## 二、从本体论意识到「关系」的丰富性

### 最初的问题

第一版只用了「属于」这一种关系：

```
SPU → 系列 → 品类 → 公司
```

训练和评测都在这一条链上打转，能造的数据非常有限。

### 本体论的启发

重新审视产品数据后，发现产品之间还存在大量被忽略的关系：

```
                    ┌── 搭载(has_chip) ──→ 麒麟9030
                    │
                    ├── 定价(has_price) ──→ ¥6499起
                    │
  Mate 80 Pro ──────┼── 支持(has_feature) ──→ WiFi7, 卫星通信...
                    │
                    ├── 定位为(positioned_as) ──→ 商务旗舰
                    │
                    ├── 前代(succeeds) ──→ Mate 70 Pro
                    │
                    ├── 同系列兄弟(same_subseries) ──→ Mate 80 Pro Max
                    │
                    └── 共享芯片(shares_chip) ──→ MatePad Pro 13.2
```

### 完整的关系类型体系

**一、分类关系（树状结构）**
| 关系 | 示例 |
|------|------|
| is_a | Mate 80 Pro → Mate 80 系列 → Mate 系列 → 手机 → 华为 |

**二、属性关系（星状结构，SPU → 值）**
| 关系 | 示例 |
|------|------|
| has_chip | Mate 80 Pro → 麒麟9030 |
| has_price | Mate 80 Pro → ¥6499起 |
| has_feature | Mate 80 Pro → WiFi7 |
| has_screen | Mate 80 Pro → 微曲屏 |
| has_battery | Mate 80 Pro Max → 6000mAh |
| positioned_as | Mate 80 Pro → 商务旗舰 |

**三、横向关系（网状结构，SPU ↔ SPU）**
| 关系 | 示例 |
|------|------|
| same_subseries | Mate 80 Pro ↔ Mate 80 Pro Max |
| same_tier | Mate 80 Pro ↔ MatePad Pro 13.2（都是 Pro 级） |
| succeeds | Mate 80 Pro → Mate 70 Pro |
| shares_chip | Mate 80 Pro ↔ Mate X7（跨品类同芯片） |
| competes | Mate 80 Pro Max ↔ Pura 90 Pro Max（同价位） |

**四、规则关系（SubSeries/Series → 属性，全称命题）**
| 关系 | 示例 |
|------|------|
| subseries_has_chip | Mate 80 系列 → 麒麟9030 系列 |
| subseries_has_feature | Mate 80 系列 → 支持 WiFi7 |

## 三、训推分离：两个互补策略

### 核心困境

知识注入 SFT 的评测面临本质悖论：

> - 测训练见过的知识 → 测的是背诵
> - 测完全没见过的知识 → 测的是基座能力，不是注入效果
> - 同一形式换表述 → 测的是模板泛化，不是知识获取

### 解题思路：让模型「多推理一步」

训练时分别教了 A→B 和 B→C，评测时问 A→C——模型需要在脑子里把两条独立的知识拼起来。

### 策略一：三段论（Syllogism）

```
图的 2-hop 路径 = 一个三段论:

  [训练] 大前提: Mate 80 系列全系搭载麒麟9030
  [训练] 小前提: Mate 80 属于 Mate 80 系列
  [评测] 结  论: Mate 80 搭载什么芯片？→ 麒麟9030
```

**适用条件**：中间关系必须是全称规则（is_a 链、已验证的 subseries_has_*），否则会出错。
**不可用的**：兄弟间属性继承（`same_subseries + has_price` 等），因为不是全称规则。

### 策略二：指代拼接（Indirect Reference）★ 主力

**核心思想**：一层直接关系训练，多层拼接关系评测。

模型训练时已学会：
- 直接关系 A：某个特性属于哪个产品
- 直接关系 B：某个产品属于哪家公司/品类

评测时，把两个关系拼在一起提问，模型必须自己组合：

> **例：Mate 80 的首配 3D 人脸**
>
> ```
> [训练] Q: Mate 80 有什么独有特性？      A: 首配3D人脸
> [训练] Q: 首配3D人脸是哪款华为手机？    A: Mate 80
> [训练] Q: Mate 80 是哪家公司的产品？    A: 华为
> [训练] Q: 华为手机有哪些系列？          A: Mate系列、Pura系列...
> [训练] Q: 华为 Mate 系列包含哪些产品？   A: Mate 80, Mate 80 Pro...
>
> [评测] Q: 首配3D人脸是哪家公司的什么产品？
>         → 模型需要: ① 首配3D人脸 → Mate 80
>                      ② Mate 80 → 华为手机
>                      ③ 拼起来 → 华为 Mate 80
> ```

**关键设计**：

- 评测时用的是「特性」这个指针间接指代产品，而不是直接问产品名
- 模型要答对，必须同时知道「特性→产品」和「产品→公司/品类/系列」
- 这两条知识在训练中是分开教的，从未在同一轮对话里出现过

### 两种策略对比

| | 三段论 | 指代拼接 |
|---|---|---|
| 图的用法 | A→B→C 正向推导 | 从叶子反向追溯 |
| 前提要求 | 中间关系必须是全称规则 | 不需要全称规则 |
| 评测题自然度 | 偏考试题 | **更像真实用户问题** |
| 答案唯一性 | 取决于推导是否确定 | 取决于特性是否独有 |
| 生成难度 | 需人工筛无效三段论 | 只需筛独有特性 |
| 在评测集中占比 | ~20% | ~80% |

## 四、完整示例：从产品属性到评测集

以 **Mate 80** 和 **首配3D人脸** 为例，贯穿全流程。

### Step 1: 产品属性（输入）

```json
{
  "name": "Mate 80",
  "company": "华为",
  "category": "手机",
  "series": "Mate 系列",
  "sub_series": "Mate 80 系列",
  "talking_points": ["麒麟9020", "6.75寸直屏", "首配3D人脸"],
  "positioning": ["商务旗舰", "直屏旗舰"],
  "price": "¥3999起",
  "status": "在售"
}
```

### Step 2: 实体抽取 + 建图

```
节点:
  SPU:      [Mate 80]
  SubSeries: [Mate 80 系列]
  Series:    [Mate 系列]
  Category:  [手机]
  Company:   [华为]
  Feature:   [首配3D人脸], [麒麟9020], [6.75寸直屏]
  Price:     [¥3999起]
  Positioning: [商务旗舰], [直屏旗舰]

边:
  Mate 80 --is_a--> Mate 80 系列
  Mate 80 系列 --is_a--> Mate 系列
  Mate 系列 --is_a--> 手机
  手机 --is_a--> 华为
  Mate 80 --has_feature--> 首配3D人脸
  Mate 80 --has_chip--> 麒麟9020
  Mate 80 --has_price--> ¥3999起
  Mate 80 --positioned_as--> 商务旗舰
  Mate 80 --positioned_as--> 直屏旗舰
```

### Step 3: 三元组 → 训练 QA（单层直接关系）

```
关系: SPU is_a SubSeries
  → Q: Mate 80 属于哪个系列？          A: Mate 80 系列
  → Q: Mate 80 系列包含哪些产品？       A: Mate 80, Mate 80 Pro, ...

关系: SPU has_feature Feature
  → Q: Mate 80 有什么独有特性？         A: 首配3D人脸
  → Q: 首配3D人脸是哪款产品的特性？     A: Mate 80

关系: SPU has_chip Chip
  → Q: Mate 80 搭载什么芯片？           A: 麒麟9020
  → Q: 哪些产品搭载麒麟9020？           A: Mate 80, Mate 70, Mate 70 Pro, ...

关系: Series is_a Category
  → Q: Mate 系列是华为什么品类？        A: 手机
  → Q: 华为手机有哪些系列？             A: Mate系列, Pura系列, nova系列...

关系: SPU positioned_as Positioning
  → Q: Mate 80 的定位是什么？           A: 商务旗舰、直屏旗舰
```

### Step 4: 评测 QA（策略二：指代拼接）

```
[评测] Q: 首配3D人脸是哪家公司的什么产品？
        → 路径: 首配3D人脸 ←has_feature-- Mate 80 --is_a→ ... --is_a→ 华为
        → A: 华为 Mate 80
        → 评分: exact_match（答对才算对）

[评测] Q: 具有「首配3D人脸」这一独有特性的是华为什么系列的产品？
        → 路径: 首配3D人脸 ←has_feature-- Mate 80 --is_a→ Mate 80 系列 --is_a→ Mate 系列
        → A: Mate 系列
        → 评分: exact_match

[评测] Q: 首配3D人脸是华为什么品类的功能？
        → 路径: 首配3D人脸 ←has_feature-- Mate 80 --is_a→ ... --is_a→ 手机
        → A: 手机
        → 评分: exact_match
```

### Step 5: 评测 QA（策略一：可靠三段论）

```
[评测] Q: 作为 Mate 80 系列的一员，Mate 80 搭载什么芯片？
        → 大前提: Mate 80 系列 subseries_has_chip 麒麟9020
        → 小前提: Mate 80 is_a Mate 80 系列
        → 结论: Mate 80 搭载麒麟9020
        → A: 麒麟9020
        → 评分: exact_match
```

## 五、方法论总结

```
输入: 产品属性 JSON
        │
  ① 实体抽取 + 关系识别
        │  实体: SPU, Chip, Feature, Price, Positioning, Series, Category, Company
        │  关系: is_a, has_chip, has_price, has_feature, positioned_as, ...
        │  规则: subseries_has_chip (从具体产品归纳全称命题)
        │
        ▼
  ② 构建知识图谱
        │  节点 × N, 边 × M
        │  每条边 → 三元组 → QA 模板 → 训练语料
        │  正问 + 反问 → 每条边产出 6-15 条训练 QA
        │
        ▼
  ③ 生成评测集（两种策略互补）
        │
        ├── 策略A [三段论] (~20%)
        │      is_a 链 + 已验证的全称规则
        │      评测 = 2-hop 正向推导
        │
        └── 策略B [指代拼接] (~80%)
               独有特性/属性 → 沿图反向追溯
               评测 = 间指代 + 多层拼接
               "有这个特性的是谁家的什么？"
        │
        ▼
输出: train.jsonl + eval.jsonl
```

### 核心公式

```
训练数据量 = 边数 × (正向模板数 + 反向模板数)
          ≈ 200边 × 6模板 = 1200条  (15个产品)
          ≈ 2000边 × 6模板 = 12000条 (89个产品)

评测数据量 = 独有特性数 × 追问层级数 + 可靠三段论数
          ≈ 20特性 × 4层级 + 10三段论 ≈ 100条  (15个产品)
```

### SFT 评测得分的可行性保障

所有评测题输出格式：
- **单值**（产品名/公司名/品类名/系列名）→ `exact_match`
- **顿号分隔列表**（多产品时）→ `list_f1`

均全自动评分，不需要人工或 LLM 辅助。
