# 知识 vs 能力：严格界定框架与对比示例

> 面向华为消费者业务客服领域基座模型训练  
> 核心问题：对于任意一个业务需求，该投给 CPT 还是 SFT/RL？  
> 回答方式：四个 Litmus Test + 大量对比示例

---

## 一、定义

```
知识 = 模型"知道什么" → 关于世界的真值陈述 → 能写进文档的
能力 = 模型"能做什么" → 关于行为的操作模式 → 写不进文档的
```

| 维度 | 知识 | 能力 |
|---|---|---|
| **本质** | 静态的、可陈述的、有标准答案的 | 动态的、情境化的、答案有优劣之分 |
| **来源** | 外部的、可文档化的 | 内化的、通过实践形成的 |
| **验证方式** | "对不对？"（有 ground truth） | "好不好？"（需要偏好判断） |
| **迁移性** | 场景间低迁移（换一个产品线知识全变） | 场景间高迁移（理解反讽的能力跨产品通用） |
| **更新频率** | 高频（新产品发布→新知识） | 低频（客服沟通的基本模式相对稳定） |
| **训练主导** | CPT | SFT / RL |

---

## 二、四个 Litmus Test（核心判据）

对任何一个具体的业务需求，依次问四个问题：

### Test 1：文档化测试（Documentation Test）

> **这个需求所涉及的内容，能不能写成一份参考文档/手册/FAQ？**

```
能写成文档 → 知识，CPT 主战场
写不成文档 → 能力，SFT/RL 主战场
```

**边界案例警示：**

> "反讽的常见表达方式有哪些" → 能写成文档（知识） → CPT  
> "此刻客户的这句话是不是反讽" → 写不成文档（能力） → SFT/RL

### Test 2：分布学习测试（Distribution Test）

> **让一个人在这个领域沉浸式观察足够多的案例，他能不能"自己悟出来"？**

```
观察足够多就能悟出来 → CPT 可以解决大部分
观察再多也悟不出来（需要反事实信号） → 需要 SFT/RL
```

**为什么观察再多也悟不出来？**
因为自然数据中没有"负样本"——你能观察到的都是"实际发生了什么"，而不是"应该发生什么"和"不该发生什么"之间的对比。

### Test 3：一致性测试（Consistency Test）

> **这个需求要求在相似情境下，模型的行为必须高度一致且可预测吗？**

```
需要高度一致且可预测 → SFT 才能保证
一致性要求低，多样性反而是优点 → CPT 更自然
```

**关键洞察：SFT 的一致性是有代价的——它会压制 CPT 带来的多样性。** "奇招涌现"需要一定的多样性空间。

### Test 4：泛化路径测试（Generalization Path Test）

> **这个需求需要泛化到什么程度？泛化的路径是什么？**

```
泛化路径是"同一种事实的不同表述" → CPT 天然擅长
泛化路径是"同一种模式的不同实例" → CPT + SFT 都需要
泛化路径是"前所未有的新场景组合" → 主要靠 CPT + 基座推理能力
```

```
          └────────────┬────────────┘

                      YES        NO

                       ▼          ▼

                              ▼          ▼

                         CPT擅长         （涌现空间）
                         （分布泛化）    + 基座推理
```

## 六、关键认知

### 6.1 CPT 对"能力"的价值不该被否定

```
SFT/RL 对能力的作用：
  ├─ 精准、可控、见效快
  ├─ 但：在表层做行为塑形，不改变底层表征
  └─ 类比：贴肌肉贴——立竿见影，但肌肉本身没变

CPT 对能力的作用：
  ├─ 间接、缓慢、不可精确控制
  ├─ 但：改变底层表征，让能力有更好的"土壤"
  └─ 类比：改变饮食和训练环境——短期看不出，但长期身体底子变了
```

**CPT 不是直接"教会"模型识别反讽，而是把模型的语义空间重塑了。** 在这个新空间里：
- "反讽句"的内部表征和"真实意图"的表征被拉近了
- 这让后续 SFT 只需要很少的标注数据就能对齐
- 也让模型在从未见过的反讽表达上有更好的泛化

**正确的说法：**

> CPT 对能力的贡献是隐式的、基础性的、通过重塑表征空间间接实现的。  
> 它不替代 SFT/RL 对能力的直接塑造，但它是 SFT/RL 发挥最大效果的前提。  
> CPT 没做透就上 SFT/RL，就像在没犁过的地上播种——也能长，但产量差很多。

### 6.2 "奇招涌现"的条件

> 涌现能力 = CPT 创建的领域表征空间 + 基座模型的通用推理能力

- **数据覆盖面要广**：不能全是"问题 A→答案 A"的工单
- **不要过早进入 SFT/RL**：SFT/RL 在 CPT 之上收束。收束过早 = 在没长好的身体上穿紧身衣
- **评测留"开放题"**：涌现能力在选择题里看不出来，在开放续写里会惊艳你
- **涌现的判据**：模型能正确处理 CPT 语料里从未出现过的客服场景

### 6.3 实操资源分配

```
总训练资源分配建议：

CPT（数据+训练）：60-70%
  ├─ 数据工程（收集、清洗、去重、配比）：~40%
  └─ 训练执行+评测迭代：~25%

SFT（数据+训练）：20-25%
  ├─ 标注数据构建（最贵的人力部分）：~15%
  └─ 训练+评测：~7%

RL（数据+训练）：10-15%
  ├─ 偏好数据标注（需要资深客服）：~8%
  └─ 训练+评测：~5%
```

**四条原则：**

1. **CPT 没做完、没做好，不要启动 SFT。** SFT 标注很贵，在 CPT 不充分的基础上做 SFT 是浪费标注预算。
2. **SFT 数据量不需要大，但需要"准"。** CPT 做好了，SFT 往往几千条优质数据就够。
3. **RL 只用于"有明确对错标准且对错代价不同的决策"。** 升级判断、安全边界、故障匹配——这些才值得用 RL。
4. **评测要分知识类和能力类，分别追踪。** CPT 后知识类指标涨 20% 但能力类只涨 3%→正常。能力类的显著提升在 SFT/RL 之后才会出现。

## 七、一句话总结

> **"能写成文档的、能观察悟出来的、不需要精确控制的" → 知识 → CPT。**  
> **"写不成文档的、需要反事实信号的、必须精确控制的" → 能力 → SFT/RL。**  
> **CPT 是土壤，SFT/RL 是耕种。没有好土壤，再好的种子也长不出好庄稼。**
