# 接口规范（Interface Contract）· pipeline_v2.01

> 目的：**每个阶段的输入/输出严格写死**，尤其**树只有一种制式**；每个输入配**校验器**。
> 公司环境不同 → 按本规范**把公司数据转成这里的样子**；跑不出结果就**对着契约修**，先跑校验器定位。

---

## 0. 铁律
1. **树只有一种制式**（见 §1）；不符合 → 先转换，别指望工具兼容。
2. **schema 只有一种制式**（见 §2.4，固定 7 列）；公司 schema → 按 7 列映射，别改列名。
3. **每一步先跑校验器**（§3）；校验不过，后面的 bug 都是它的连锁反应。
4. 名字、路径：**不允首尾空格**；分隔符统一用 `" > "`（空格-大于-空格）。

---

## 1. 树（唯一制式）

### 1.1 结构
```json
{
  "name": "华为", "type": "公司",
  "children": [
    {"name": "手机", "type": "产线", "children": [
      {"name": "Mate 系", "type": "系列", "children": [
        {"name": "Mate 80 系列", "type": "代", "children": [
          {"name": "Mate 80", "type": "SPU"}
        ]}
      ]}
    ]}
  ]
}
```
### 1.2 规则（校验器强制）
- 每节点：`name`(非空, **无首尾空格**) + `type` + `children`(数组, 可省略/空)。
- `type` ∈ `{公司, 产线, 系列, 代, SPU}`，且**层级顺序**：公司 → 产线 → 系列 → 代 → SPU（可缺层，不可乱序）。
- **同级同名**禁止；**name 内含 `>`** 禁止。
- `path` = 各层 `name` 用 `" > "` 连接。示例：`华为 > 手机 > Mate 系 > Mate 80 系列`。
- **实体（可挂 facts 的最小单位）= 叶子节点**（一般 `SPU`）；**节点级知识可挂任意节点**（见 §4）。

### 1.3 为什么要严格
本次实验就栽在"树制式小问题"（**节点名带空格**）→ 路径对不上 → 挂载失败、题型错乱。
**换树时最容易出的坑就是空格/分隔符/层级**，校验器专治这个。

---

## 2. 数据（schema 先行）与其它 I/O

### 2.1 数据（`数据.jsonl`，每行一实体）
```json
{"entity": "Mate 80 Pro", "tree_path": "华为 > 手机 > Mate 系 > Mate 80 系列", "triples": [{"relation": "搭载芯片", "value": "麒麟9030"}]}
```
- `tree_path` = **实体父节点的 path**（**不含实体名**）；`entity` 单独给。
- 校验：`tree_path` 必须是树中节点的 path；`tree_path > entity` 必须是 `tree_path` 的子节点。
- `triples`：`relation` 走 schema（元特性表）；`value` 非空。

### 2.2 各阶段 I/O（严格）
| 阶段 | 输入（严格） | 输出（严格） |
|---|---|---|
| 0 建议表 | `数据.jsonl` | `出题建议.csv`（列：关系,出现次数,出对比,权重,备注） |
| 1 mindmap | `数据.jsonl` | `mindmap.txt`（ASCII） |
| 2 SCPT | `数据.jsonl` + `--category` | `{input,output,_meta}` → `scpt_entity_llm.jsonl` |
| 3a/3b 出题 | `数据.jsonl`(+建议表) + `--category`；3a 另需 `prompts/<题型>/` | `{type,q,a}`，文件名=`<题型>.jsonl` |
| 4 CoT | 题型 jsonl + `数据.jsonl`(+语料) | `{question, answer, response, style, _parts, _meta}`（见 §2.5） |
| 5 组装 | `<pkg>/cot/*.jsonl` | `{input, output}` → `sft/sft_cot.jsonl`（`--output-mode`，D-7） |
| 6 审阅 | `<pkg>`（题型 jsonl + cot/ + scpt/） | `review_all.html` |

### 2.3 包目录（严格）
```
<pkg>/
├─ <题型>.jsonl         # 1-1 … 2-6, L1/L2（文件名=题型）
├─ cot/<题型>.jsonl
├─ scpt/*.jsonl         # 名字含 llm / leaf
├─ sft/sft_cot.jsonl
└─ review_all.html
（中间物/元数据放 <pkg>/_meta/，不要放根！否则会被审阅页当成题型）
```

### 2.4 schema（元特性表）唯一制式  ← **D-4 扩展，公司务必对齐**
文件：`schema_<产线>.csv`（一个产线一张）。**固定 7 列，列名与顺序固定**：

| 列名 | 必填 | 说明 |
|---|---|---|
| `关系` | ✅ | 谓语名（= 出题的 relation），如 `搭载芯片` |
| `值域` | ✅ | 可选范围/口径（枚举全列，或写 `自由文本`） |
| `口径` | ⬜ | 定义/单位/边界（如"厚度不含凸起"） |
| `适用层级` | ✅ | ⊆ `{SPU, 代, 系列, 产线}`，多个用 `|`（如 `SPU`、`系列`） |
| `语义` | ✅ | `事实` / `全称` / `典型` / `规则`（**只这 4 个**） |
| `可否对比` | ✅ | `0` / `1`（驱动 2-6 跨产品对比） |
| `备注` | ⬜ | 例外/注意事项 |

> **D-4 的"两列"就是这里的 `适用层级` + `语义`**：节点级知识（命名后缀/系列别名/全称特性）**不是另立**，而是本表里 `适用层级=系列` 的那些行。

**铁律（schema）**：
- **不改列名、不改 `语义` 取值**；要扩展 → **加行**，或给 `适用层级` 加取值。
- 公司已有 schema → 按这 7 列**映射**过来（不认的行/列单独备注）。
- **只加不破**：v1(5 列) → v2(7 列)，**旧版必须被认识**（校验器 warning 不报错）；升级用 `0_migrate_schema.py`（**留痕**到 `*.migrate.md`），见 `schema版本记录.md`。
- 校验：`0_validate_schema.py`（列名/取值/枚举；识别 v1/v2）。

### 2.5 CoT 组件契约（**无损装配 / 风格可切换**）  ← **D-8**
一条 CoT = **原件(`_parts`) + 成品(`response`)**：
```json
{"question":"…","answer":"…","style":"short",
 "_parts":{"struct_full":"…","struct_used":"…","corpus":"…",
           "reasoning":"…","reasoning_short":"…","reasoning_steps":["…"],"answer":"…"},
 "response":"…（按 style 装配）"}
```
**铁律**：
- **`_parts` 永久保留**（"原件收藏"）→ 换风格 / 做对比 **0 LLM、秒级**；
- `response` 只是某一种装配，**不是唯一真相**；
- 旧数据无 `_parts` 也能换风格：`4b_cot_restyle.py` 会**从 `response` 反解析**。

`style ∈ {raw, used, short, steps}`：
| style | 内容 | 用途 |
|---|---|---|
| `raw` | 知识结构全文 + 原文 + 推理 + 答案 | 现状（最全） |
| `used` | **紧凑结构（仅涉及实体）** + 推理 + 答案 | 中等 |
| `short` | **短推理 + 答案** | **推荐给 8B（D-7）** |
| `steps` | 紧凑结构 + **分步推理** + 答案 | D-6（需 `reasoning_steps`） |

**工具**：
- `4_gen_cot.py`（生成；`--style`、`--reasonings both|normal|short`；**写 `_parts`**）
- `4b_cot_restyle.py`（**换风格，0 LLM**；兼容旧数据）
- `5_assemble_sft.py --output-mode full|short|used|answer`（**SFT 目标形态**，D-7 可决策点）

## 3. 校验器（每个输入都有）
| 校验器 | 校验对象 | 抓什么 |
|---|---|---|
| `0_validate_tree.py` | 树 json | 空名/空格/层级乱序/同级同名/含`>` |
| `0_validate_data.py` | 数据 jsonl（+树） | tree_path 不在树里 / entity 非 tree_path 子节点 / triples 空 |
| `0_validate_schema.py` | 元特性表 `schema_<产线>.csv` | 列名/顺序不对 / `语义` 非法 / `适用层级` 非法 / `可否对比` 非 0-1；**识别 v1 旧版** |
| `0_migrate_schema.py` | schema v1→v2 | 自动补 `适用层级`/`语义` 并**留痕** `*.migrate.md` |
| `validate_nodes.py`（attach_v1.01） | 节点知识 | path 不在树 / semantics 非法 |
| `validate.py`（树归一） | 数据 tree_path | 连续"系列"层 / 末段是实体名 |

---

## 4. 节点级知识（facts 挂任意节点）
```json
{"path": "华为 > 手机 > Mate 系", "level": "系列", "facts": [
  {"relation": "命名后缀", "value": "Pro / Pro Max / RS 非凡大师", "semantics": "规则"}]}
```
- `path` 定位（**不依赖树形状** → 换树也能挂，只要 path 对得上）；
- `semantics ∈ {全称, 典型, 规则}`（必填）。

---

## 5. 排错表（对着契约修）
| 症状 | 最可能原因 | 修哪 |
|---|---|---|
| 节点级知识挂不上 | 树/节点 **名字带空格**、分隔符不是 `" > "` | 跑 `0_validate_tree.py`，清洗 name |
| 出题里实体/层级对不上 | `数据.tree_path` **不含实体应为父节点路径** | 跑 `0_validate_data.py` |
| 审阅页冒出奇怪"题型" | 中间文件（tree/nodes/数据）**放在了 pkg 根** | 挪进 `_meta/` |
| 2-4 代际题乱 | 实体**无发布时间**却被排序对比 | 数据补发布时间，或跳过（已内置） |
| 2-6 没题 | 建议表里"出对比=1"的关系没配对/太少 | 改 `出题建议.csv` |
| 公司 schema 工具不认 | 列名/列序/`语义`取值不符 §2.4 | 按 §2.4 映射成 7 列，跑 `0_validate_schema.py` |
| 挂载/渲染/出题结果不符预期 | 树制式不达标 | **先 §3 校验，再谈下游** |

### 一句话
> **先对齐"树/数据"的制式与校验，再谈结果**；公司版跑不通，就**按本规范逐项对齐、重跑校验器**。
