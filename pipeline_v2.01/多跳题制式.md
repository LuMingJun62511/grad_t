# 多跳题（Multi-hop）制式 · D-5

> 定义：**先用若干特性"定位"到一个产品，再"上溯"到它的父层级（系列/代），最后问父层知识**。
> 例：`支持 LTPO 且是华为手机的那款，它所属的系列，别名叫啥？ → Mate 系（Mate）`
> 同构：`讲中文、出了武松的地方（山东）→ 那儿的人爱吃啥？→ 大葱`

---

## 1. 题型号：**`3-1`（已定）**
- `3-1` = 新家族 `3-x` = **综合/多跳推理**。
- **定位**：比 1-x/2-x **上一个台阶**，**更偏"评测性质"**（考跨层推理，不是记忆）。→ 在 D-2 分层里归 **档 3（多跳）**，**按比例少量配**，不铺量。

## 2. 契约（**不破坏现有 `{type,q,a}`**）——多跳路径放 `_meta`
```json
{
  "type": "3-1",
  "q": "支持 LTPO 且是华为手机的那款，它所属系列还有别的叫法吗？",
  "a": "有，Mate 系也叫 Mate",
  "_meta": {
    "hops": [
      {"n": 1, "do": "定位", "from": ["支持LTPO", "华为手机"], "to": "Mate 80 Pro"},
      {"n": 2, "do": "上溯", "rel": "is_a", "to": "Mate 80 系列"},
      {"n": 3, "do": "取父层知识", "rel": "系列别名", "from": "Mate 系", "value": "Mate"}
    ]
  }
}
```
> 下游 CoT/组装/审阅**不改契约**：`_meta` 是附加，最下游按 `hops` 分步推理。

## 3. 构造规则（可程序化，也有唯一性校验）
1. **特征**：取某 SPU 的 **≥2 条** 事实（尽量跨关系）；
2. **定位唯一性**：这些特征在本品类里**只命中一个** SPU，否则弃题（这是多跳最容易错的第一步）；
3. **上溯**：用 `is_a` 到父节点（系列/代）；
4. **父层知识**：取父节点的 `facts`（优先 `语义=规则/全称`，如 命名后缀/别名/全称特性）；
5. 答案 = 父层知识的值。

## 4. CoT 要求（你担心的下游）
- **必须分步**：`特征 →(定位) 产品 →(is_a) 上溯 →(父层知识) 结论`；
- **每步 grounded**：定位步引用数据事实，上溯步引用树，父层步引用节点知识；
- **定位唯一性**已在校验里保证（否则第一步就崩）；
- **每跳单独计分**（勿把多跳当一跳）——与 D-6 的"按题型分步"一致。
