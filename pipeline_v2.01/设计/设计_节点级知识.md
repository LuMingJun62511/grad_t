# 设计 · 节点级知识（知识不只挂最低层）

> 2026-10-07。回答："这是设计级问题吗？是颠覆还是加题型？"

## 结论
**设计级，但不颠覆。** 本质是把「实体 = 叶子(SKU)」**推广为「实体 = 树的所有节点」**，再给事实加 `层级` + `语义(全称/典型/规则)`。
- **向后兼容**：旧数据（facts 全在叶子）无需改。
- **不是重来**：产品树、题型框架、渲染、CoT 都能复用；2-5 已经"半只脚踏入"（它的输入已有 `series_entity/series_triples`）。

## 一、被牵动的四层
| 层 | 旧假设 | 新 |
|---|---|---|
| 数据模型 | 只有 SKU 挂 facts | 任意节点挂 facts + `semantics` |
| 渲染 | 中间层只有名字 | 路径上祖先节点也有 facts → 需**按分支裁剪** |
| 题型 | 全在叶子间 | 答案/指代物可为**中间层实体**；新增"层级/规则题" |
| 真值 | 按 SKU 判唯一 | **按层级**判（系列 vs 成员） |

## 二、核心新概念（必须拍）
**层级事实的继承语义**：
- **全称**：所有成员成立 → 可继承/三段论（"Mate 系列全用 X"）。
- **典型**：多数成立 → 不继承，仅背景。
- **规则**：命名/构成规则 → 用于判断与生成（"Mate 系列只用 Pro/Pro Max 后缀"）。

> 不标这三者，题型不可靠（典型当全称 → 造错事实）。

## 三、数据模型 v2（草案）
```json
{
  "node": "Mate 系列", "level": "系列",
  "facts": [
    {"relation": "命名后缀", "value": "Pro / Pro Max", "semantics": "规则"},
    {"relation": "搭载芯片", "value": "麒麟X90 系列", "semantics": "全称"}
  ]
}
```
叶子（SKU）同构，只是 `level=SPU`。**facts 的 relation 仍走同一份 schema / 元特性表。**

## 四、渲染（防臃肿）
- SCPT/CoT 的 mindmap：**路径 + 当前节点 facts + 祖先节点 facts**（族谱式），兄弟仅列名；
- 不再渲染全树所有 facts。

## 五、题型影响
- **新增**：层级/规则题（指向中间节点）：
  - "Mate 系列有哪些命名后缀？"（系列→R→O）
  - "Mate 80 会有 Ultra 版吗？"（规则 + 归属 → 否定推理）
- **改造**：2-5 上级归纳 = **直接读系列 facts**（不再从成员算交集），并能区分"真·全系(全称)" vs "典型"。
- **真值**：倒排索引加 `level` 维度。

## 六、分步落地（增量）
1. 数据模型 v2 + `validate.py` 增校验（节点 facts + semantics 必填）。
2. 渲染裁剪（路径+祖先 facts）。
3. 题型：加层级/规则题；2-5 改读节点 facts。
4. SCPT/CoT：路径上系列 facts 进 mindmap。
