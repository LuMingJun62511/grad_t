# 决策表簿（Decision Table Log）

> **用途**：把设计判断沉淀成"**情形 / 落哪 / 例子 / 依据**"四列表，供本人回看与**多轮对话引用**。
> **约定**：表编号 `D-x`；**只追加、不改历史**（要改就新增一表并标注取代）；每表附一句"怎么用"。
> **我的习惯（自定）**：今后凡是设计级判断，**先出这种表，再写正文**；并把表登记到这里。

---

## 表 D-1 · 节点级知识 → 落哪（题型维度）

**怎么用**：一句话判据 = **答案落在哪一层 + 是否跨层推理**。

| 情形 | 落哪 | 例子 | 依据 |
|---|---|---|---|
| 答案是**中间节点**（系列/代） | **新题（层级正向）** | "Mate 系的命名后缀有哪些？" | 现有题型答案都在叶子 |
| 需**规则+归属+否定**推理 | **新题（规则题）** | "Mate 80 系列会有 Ultra 版吗？→ 不会" | 叶子事实做不到 |
| 答案=叶子，**真值来自上层全称** | **融入 1-1**（继承） | "Mate 80 的芯片？"（由系列全称继承） | 见语义=全称 |
| 真值来源从"成员交集"→"节点 facts" | **改造 2-5** | "全系标配？"（直接读系列 facts） | 2-5 已半只脚进来 |
| 答案=中间节点（**反向**） | **扩展 2-1** | "后缀只有 Pro/Pro Max 的是哪个系列？→ Mate 系" | 2-1 答案本可为节点 |
| 规则 → 造否定 | **融入 1-4** | "Mate 80 系列有 Ultra 版，对吧？→ 不对" | D1 否定样本的"真边界" |

**一句话原则**：节点级知识不是"多一套题型"，而是**给题型体系加一个『层级维度』**——缺的补 2 个新题，其余放宽"答案层/真值来源"。

## 表 D-2 · 知识分层 / 放宽档（可控）

**怎么用**：出题时可配"**混层上限**"（放宽有度）；**单层与混层都允许**，按比例配。

| 档 | 名字 | 知识跨度 | 例子 | 备注 |
|---|---|---|---|---|
| 0 | 单层 | 同层、单跳 | "Mate 80 的芯片？" | 不放宽 |
| 1 | 跨一层 | 继承 / 归属 | "Mate 80 属于哪个系列？" | 叶子↔上层 |
| 2 | 跨两层 | 规则 / 层级判断 | "Mate 80 会有 Ultra 版吗？" | 需上层规则 |
| 3 | 多跳 | 两条以上独立知识拼接 | "屏幕A且有X架构的那款，其系列别名？" | 台阶二多跳 |

**配比参数（建议）**：`档0:档1:档2:档3` 可调（如 `5:3:1:1`）；**默认不许全放档3**（易错且难核验）。

## 表 D-3 · L1/L2/L3 的定位（层级题要不要单列）

**怎么用**：判据 = **答案落在哪一层 + 是否跨层推理**；**形态是否与已有题型重复**。

| 情形 | 落哪 | 例子 | 依据 |
|---|---|---|---|
| 答案=中间节点（系列/代） | **新题型 L1**（系列正向） | "Mate 系的命名后缀？" | 现有题型答案都在叶子 |
| 需规则 + 归属 + 否定 | **新题型 L2**（规则/判断） | "Mate 80 系列会有 Ultra 版吗？→不会" | 叶子事实做不到 |
| 答案=叶子、真值来自上层**全称**继承 | **不单列**；作 **1-1 的"继承变体"**（标 `source=继承/三段论`） | "Mate 80 Pro 的屏幕类型？"（由系列全称继承） | 形态=1-1，仅真值来源不同；且**强依赖"全称"可信**，不可靠 |

**结论**：L1/L2 立为新题型（并**各配一套 prompt**，同 3a）；**L3 撤销题型、降级为 1-1 的来源标签**（先不做）。

## 表 D-4 · schema ↔ 节点级知识（一套还是两套？）

**怎么用**：判据 = **谓语的"适用层级"与"语义"**。

| 情形 | 落哪 | 例子 |
|---|---|---|
| 事实谓语（实体属性） | **schema**，`适用层级=SPU` | 芯片 / 屏幕 / 电池 |
| 规则谓语（命名/别名） | **schema**，`适用层级=系列`，`语义=规则` | 命名后缀 / 命名排除 / 系列别名 |
| 全称特性 | **schema**，`适用层级=系列`，`语义=全称` | 全系标配 LTPO |
| 典型特征 | **schema**，`语义=典型` | 系列一般配 X |

**结论**：**一套 schema + 两列（`适用层级` / `语义`）**；**不另立"节点级 schema"**。
→ 系列级知识与 schema **是一个思想**；落地就是**"纳入 schema（加层级/语义两列）"**。

## 表 D-5 · 多跳题（特征定位 → 父层知识）

**怎么用**：判据 = **是否需要"先定位、再上溯、再取上层知识"多步**。

| 情形 | 落哪 | 例子 | 依据 |
|---|---|---|---|
| 用若干特性**定位**某产品 | 指代（已有 2-1 思路） | "支持 LTPO 且是华为手机的那款" | 需唯一性校验 |
| 再问**父层级**（系列/代）知识 | **新题型：多跳（定位+上溯+父层）** | "…那款所属系列，别名叫啥？→ Mate 系（Mate）" | 跨两层 + 多步 |
| 仅"成员继承系列全称" | 不单列（原 L3，撤） | "Mate 80 Pro 的屏幕类型？" | 无定位、形态=1-1 |

**下游 CoT 注意**（你提的）：
- CoT **必须分步**：`特征→(定位)产品→(is_a)系列→(父层知识)答案`，**每步 grounded**；
- **定位唯一性**要程序校验（否则第一步就错）；
- 父层知识若为 `典型/规则`，语义要标（影响可信度）；
- **每跳单独计分**（勿把多跳当一跳）。

## 表 D-6 · 出题思路 → CoT 推理路径（**CoT 按题型分模板**）

**结论**：CoT 的"推理"部分**不该用通用写法**，应**复用该题型的"出题思路"**。
**理由**：出题 prompt 本就编码了"从哪些知识、经什么关系得到答案"——**这就是答案的推理链**；CoT 只需**反向走同一条链**并逐步 grounding。
**落地**：`prompts/<题型>/` 增 `reasoning.txt`（或全局 `推理路径.json`：type→步骤）；`4_gen_cot.py` 读它按题型分步推理，无则回退通用。**附带好处**：CoT 天然分步、可核验、**可每跳计分**（多跳 3-1 直接复用）。

| 题型 | 出题思路（怎么造） | CoT 推理路径（怎么推） |
|---|---|---|
| 1-1 | 某实体某属性直问 | 定位实体分支 → 取该关系值 → 结论 |
| 1-2 | 实体归属系列 | 定位实体 → 读 is_a → 结论 |
| 1-3 | 实体特性列举 | 定位实体 → 汇总特性 → 结论 |
| 1-4 | 属性值真/假 | 定位实体 → 取实际值 → 比对 → 否/是 |
| 2-1 | 特征→定位实体 | 逐特征试配 → 去重(唯一命中) → 结论 |
| 2-2 | 关系值→列举实体 | 遍历候选 → 按值过滤 → 结论 |
| 2-3 | 两实体同关系对比 | 各取两实体值 → 比较 → 结论 |
| 2-4 | 代际同关系变化 | 排代际 → 取同关系 → 比变化 → 结论 |
| 2-5 | 全系共性 | 取成员 → 求交 → 结论 |
| 2-6 | 跨产品同关系对比 | 各取两实体值 → 比较 → 结论 |
| L1 | 系列节点正向 | 定位系列节点 → 取节点知识 → 结论 |
| L2 | 规则判断(白/黑名单) | 取规则 → 判归属 → 否/是 |
| 3-1 | 特征定位+上溯+父层 | 定位产品 → 上溯 → 取父层知识 → 结论 |

## 表 D-7 · SFT 目标形态（**面向小模型 / 8B**）

**怎么用**：判据 = **这条内容对 8B 是"可学的推理"还是"抄上下文"**；长度预算优先给"可学的"。

| 情形 | 落哪 | 依据（实测） |
|---|---|---|
| 目标是"短、可学" | **`output` = 短推理 + 答案** | 现 `output` 1568 字中 **1458(93%) 是〔知识结构〕**，推理仅 83 字 |
| 〔知识结构〕块 | **移出 `output`**：检索式→放 `input`；纯参数化→**不用** | 它是"照抄上下文"，非推理；8B 学它有害 |
| 推理段长度 | **默认"短"**（一句、按题型路径 C 式） | C≈54 字 < A≈103 < **B≈156（最长）** |
| 何时用"分步 B" | 仅当需要**每跳计分/强核验**（如 3-1 评测） | B 可核验但最长，非训练目标首选 |

**结论**：**抠推理那几十字收益小；把〔知识结构〕移出 `output` 收益大（−92% 长度）**。
**三选一待定**：(a) output=短推理+答案，结构进 `input`；(b) 同 (a) 但结构完全去掉（纯参数化）；(c) 保留结构但**压缩成"只列用到的 1~2 条"**。

## 表 D-8 · CoT 组件化（**无损装配 / 风格留作可决策点**）

**怎么用**：判据 = **本地能否立刻判断优劣？不能 → 就别定死，留原件 + 开关**。

| 情形 | 落哪 | 依据 |
|---|---|---|
| 无训练条件、难判断长短优劣 | **风格不定死**，做成开关（`style`），**原件永久保留** | 本地训不了，定了也可能是错的 |
| CoT 是"组装"的 | 一条 CoT = **`_parts`(原件) + `response`(某一种装配)** | 随时换风格/对比，**0 LLM、秒级** |
| 历史数据 | `4b_cot_restyle.py` **从 `response` 反解析**也能换风格 | 旧 451 条不用重跑 |
| SFT 目标形态 | `5_assemble_sft.py --output-mode` | D-7 的可决策点 |

**产物**：`tools/{cot_parts.py, 4_gen_cot.py, 4b_cot_restyle.py, 5_assemble_sft.py}`；契约见 `接口规范.md` §2.5。
**实测**：耳机 1-1 共 207 条，`raw(1477 字) → short(85 字)` 秒切、0 LLM。

## 表 D-9 · 语料融合路径（**语料 → 入库，不是 → SCPT**）

**怎么用**：判据 = **这条内容是"证据"还是"真相"**；**语料=证据，树/schema=唯一真相**。

| 情形 | 落哪 | 例子 |
|---|---|---|
| 外部语料进来 | **先抽取 → 归位**，**不直接生成 SCPT** | 「X 支持蓝牙5.2」→ (X, 蓝牙版本, 5.2) → 绑到树下 |
| 抽出但绑不上 实体/谓语 | **候选池**待归类（**不许散放成孤岛**） | 新谓语 → 候选谓语表；新实体 → 候选实体 |
| 想让语料"多出题" | 扩 **schema/树** → 题空间随之扩大 | 加谓语列 → 新题自然覆盖 |

**结论**：现在缺的是 **ingest 环节**，**不是改 SCPT**；"别人给语料只能出受限题"是 **schema 先行的作用域控制**（不是体系缺陷）。

## 表 D-11 · 大表 = schema/数据的**统一载体**；按【产线 × 层级】分表

**怎么用**：判据 = **同一张表的"空/满"两态 + 谓语的适用层级**。

| 情形 | 落哪 | 例子 |
|---|---|---|
| **空表** | = **schema**（列=谓语/元属性） | `模板_耳机_产品级.csv` |
| **填满** | = **三元组（数据）** | `大表_耳机_产品级.csv`（`0_matrix_to_triples.py` 反向回 `数据.jsonl`） |
| 产品级谓语 | **产品级表**（行=SPU） | 佩戴形态 / 续航 / 芯片 |
| 系列级谓语 | **系列级表**（行=系列节点） | 命名后缀 / 系列别名 / 全称特性 |
| **每条产线** | **一张大表**（产品级 + 系列级各一张） | 手机 / 耳机 / 平板 / 笔记本 / 汽车 / 手表 |

**依据**：层级混在一张 = **对角矩阵**（右上/左下一堆 0）。**分层 → 不药而愈**。
**产物**：`tools/{0_make_matrix.py（出表）, 0_matrix_to_triples.py（反向）, 0_analyze_matrix.py（整理建议）}`。

## 表 D-12 · schema 每列必须带【来源标注】（防"我自作主张"）

**怎么用**：判据 = **这列是"你定的 / 数据里的 / 我拟的"**。

| 情形 | 落哪 | 例子 |
|---|---|---|
| 你明确要的 | 备注 `[你定]` | 命名后缀、系列别名 |
| 数据里已有的 | `[数据]` | 搭载芯片、售价 |
| **我提议的** | `[我拟]`（**默认存疑，需你确认**） | 形态、存储、刷新率、特性、折叠组 |
| 承自决策表 | `[D-x]` | 全称特性 `[D-4]` |

**反面教材**：`命名排除` —— 我为了 L2 规则题**擅自加的**，其实可由"`命名后缀` 为**完备白名单**"**派生**，不必单列。（已删）
**结论**：**我不再把未确认的谓语混进 schema**；每列必带来源，`[我拟]` 的默认不算数、等你拍。

## 表 D-13 · schema 列序 = 优先级（列有高低）

**怎么用**：判据 = **这列对"看/比/出题"多重要**。

| 情形 | 落哪 | 例子 |
|---|---|---|
| 列的价值 | 备注打 `[价值:顶/高/中/低]` | 形态/产品定位=`顶`；售价/芯片/屏幕/电池=`高` |
| 排序规则 | **同层级内**：价值 → 可否对比 → 原序 | `tools/0_sort_schema.py` |
| 体现在哪 | **schema 行序 = 大表列序 = 审阅页列序** | 高价值靠左 |

**结论**：**调优先级 = 调 schema 行序 / 价值标注**；高价值列**优先进 `可否对比`（2-6）与出题**。
**产物**：`tools/0_sort_schema.py`。
